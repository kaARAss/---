# Та-Ис шоу — сайт и админка

## Публикация и вход

Существующий дизайн и медиа сохранены. Главная страница работает на GitHub Pages без Node.js.

### GitHub Pages (текущий способ размещения)

1. Откройте `/admin` или `/admin/`. Логин — `kaARAss`, вход — по паролю владельца. Открытого пароля или токена в файлах сайта нет.
2. `admin-vault.json` содержит только зашифрованный GitHub-токен. Ключ получается из пароля с PBKDF2-SHA256 (600 000 итераций, случайная соль); шифрование AES-256-GCM с новым nonce. Данные привязаны к этому репозиторию.
3. Пароль не отправляется по сети. Токен после расшифровки хранится только в памяти вкладки и отправляется исключительно GitHub API для проверки прав и публикации. После перезагрузки нужен повторный вход. Черновики и выбранные файлы хранятся отдельно в IndexedDB без пароля и токена.
4. «Сохранить» сохраняет **черновик**, а «Опубликовать» отправляет контент и материалы одним коммитом. Дождитесь успешной сборки GitHub Pages в Actions.

**Ограничение статического размещения:** это не серверная авторизация. Зашифрованный файл публичен; злоумышленник может пытаться подобрать пароль офлайн, без ограничений частоты. Успешный подбор раскроет токен. Используйте длинный уникальный пароль и токен с ограниченным сроком действия, доступом только к `kaARAss/---` и Contents: Read and write. Старый токен, ранее встроенный открытым текстом, отзовите отдельно: удаление из файлов не удаляет Git-историю.

### Замена пароля или истёкшего токена

На своём компьютере задайте `TAIS_GITHUB_TOKEN` и `TAIS_ADMIN_PASSWORD` в приватном окружении (можно в игнорируемом `.env`) и запустите:

```bash
node --env-file=.env scripts/configure-admin-vault.cjs
```

Опубликуйте только новый `admin-vault.json`; никогда не публикуйте `.env`. При утечке пароля или токена замените **оба** и отзовите старый токен: предыдущие зашифрованные версии остаются в Git-истории. Замена только пароля не защищает старый токен от подбора старого пароля. Если конфигурации нет, предусмотрен режим входа личным токеном для первоначальной настройки.

### Серверный режим (не требуется для GitHub Pages)

Node.js 20+; `npm ci`. Скопируйте `.env.example` в `.env` (не коммитьте), задайте уникальный пароль от 12 символов. Запустите `node --env-file=.env server.js` за HTTPS-прокси.

Конфигурация, хеш пароля и серверный GitHub-токен хранятся **вне публичной папки**: по умолчанию `~/.tais-show/admin-config.json`, можно задать `TAIS_CONFIG_FILE`. Перед первым запуском настройте `TAIS_ADMIN_PASSWORD`; смена пароля производится из админки. Изменение пароля аннулирует ранее выданные сессии. При своём доверенном reverse proxy используйте `TAIS_TRUST_PROXY=1`, чтобы HTTPS-cookie получали Secure.

Публичная загрузка файлов закрыта; загрузка требует сессии и проверяет формат/размер. Сервер не запускает shell-команды из имён файлов и не публикует конфигурацию, пароли или токены в GitHub. Для серверной публикации задайте `TAIS_GITHUB_TOKEN` только через окружение.

## Данные и защита от повторной поломки

- Один JSON-блок `script#site-content` в `index.html` — источник шоу, материалов, контактов, баннеров и кадрирования.
- `content-utils.js` валидирует и безопасно сериализует данные; `site-content.js` читает их без `eval`.
- Админка больше не переписывает JavaScript, CSS или собственный HTML при загрузке материалов. Последовательность `\\n` не превращается в исполняемый код.
- В продакшен не попадают `blob:`-адреса превью. Новые файлы получают новые имена, чтобы старый кэш не скрывал замену.
- Пустые данные, неподдерживаемые файлы и ошибочные ответы не выдаются за успешную публикацию.
- Конкурирующая публикация блокируется, чтобы не затереть изменения другой сессии.
- При сетевом сбое черновик и файлы остаются для повторной попытки. Кнопка блокируется на время публикации.

Онлайн-оплата, билеты и сертификаты не подключены: в этом репозитории нет их рабочего платёжного backend. Текущий публичный заказ, как прежде, идёт через MAX/Telegram; устаревшие формы не должны отправлять фиктивную оплату. Ссылка на отсутствующее пользовательское соглашение заменена ссылкой на контакты; юридические условия не сочинялись.

## Порядок фото и видео в карточке

В админке у каждого материала есть кнопки «↑ Выше» и «↓ Ниже» — в списке «Материалы карточки справа» и в нижней сетке материалов. Фото и видео перемещаются в одном общем списке; превью карточки обновляется сразу. Первая позиция не перемещается выше, последняя — ниже. Порядок сохраняется в черновике автоматически; для изменения на публичном сайте нажмите «Опубликовать». Перестановка не меняет файлы, подписи, кадрирование и превью видео.

## Превью видео

При добавлении или замене видео админка создаёт JPEG из самого ролика. Проверяются несколько кадров примерно из 18–92% длительности (у обычных роликов — не раньше 3 секунд). Чёрные/почти чёрные и пустые белые кадры пропускаются; среди остальных выбирается наиболее содержательный по яркости и деталям. Обложка шоу больше не используется вместо кадра видео.

Видео и JPEG сохраняются вместе в черновике и публикуются одним коммитом. Пока создаётся превью, редактор и публикация временно заблокированы. Если браузер не умеет декодировать формат или видимый кадр не найден, файл не добавляется, остальные данные не меняются; появляется сообщение об ошибке. Для таких файлов используйте MP4/H.264. Исходное видео не обрезается и воспроизводится с начала — сдвигается только кадр превью.

## Проверки

```bash
npm ci
npm test
# Локальный статический сайт для интеграционных тестов:
python -m http.server 8765 --bind 127.0.0.1
# В другом терминале (после установки Chromium для Playwright):
npx playwright install chromium
npm run test:browser
```

В браузерных тестах GitHub полностью подменён: настоящий токен и настоящий репозиторий не используются. Проверяются вход, сохранение/восстановление черновика с файлами, материалы в двух разных шоу, отдельные мобильные фото, кадрирование, баннеры, контакты, две публикации, сбой/повтор, десять окон шоу и галереи, мобильные кнопки и настоящие touch-свайпы. Для своего Chromium задайте `CHROMIUM_PATH`; для другого локального адреса — `TAIS_TEST_URL`.
