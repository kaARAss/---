# Та-Ис шоу — сайт и админка

## Публикация и вход

Существующий дизайн и медиа сохранены. Главная страница работает на GitHub Pages без Node.js.

### GitHub Pages (текущий способ размещения)

1. **Отзовите старый токен**, который был встроен в публичную старую админку. Удаление из текущих файлов не удаляет его из Git-истории. Считайте его скомпрометированным.
2. Создайте в GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens **личный токен**: только репозиторий `kaARAss/---`, разрешение **Contents: Read and write**, ограниченный срок действия.
3. Откройте `/admin` или `/admin/`. В поле «Личный GitHub-токен» введите новый токен. Не передавайте его в чат и не вставляйте в исходники.
4. Токен существует только в памяти текущей вкладки. После перезагрузки страницы потребуется войти снова. Черновики и выбранные файлы при этом восстанавливаются отдельно из IndexedDB в этом браузере.
5. «Сохранить» сохраняет **черновик**, а не публикует сайт. «Опубликовать» проверяет все данные и загружает материалы + новую версию контента одним коммитом. Дождитесь успешной сборки GitHub Pages в Actions. Срок развёртывания не гарантирован.

Старые встроенные пароли больше не принимаются. Без собственного сервера статическая HTML-страница не может надёжно защитить запись в GitHub общим паролем. Видимость админки сама по себе не даёт посетителю права публиковать: для этого нужен GitHub-доступ.

### Серверный режим (не требуется для GitHub Pages)

Node.js 20+; `npm ci`. Скопируйте `.env.example` в `.env` (не коммитьте), задайте уникальный пароль от 12 символов. Запустите `node --env-file=.env server.js` за HTTPS-прокси.

Конфигурация, хеш пароля и серверный GitHub-токен хранятся **вне публичной папки**: по умолчанию `~/.tais-show/admin-config.json`, можно задать `TAIS_CONFIG_FILE`. Перед первым запуском настройте `TAIS_ADMIN_PASSWORD`; смена пароля производится из админки. Изменение пароля аннулирует ранее выданные сессии. При своём доверенном reverse proxy используйте `TAIS_TRUST_PROXY=1`, чтобы HTTPS-cookie получали Secure.

Публичная загрузка файлов закрыта; загрузка требует сессии и проверяет формат/размер. Сервер не запускает shell-команды из имён файлов и не публикует конфигурацию, пароли или токены в GitHub. Для серверной публикации задайте `TAIS_GITHUB_TOKEN` только через окружение.

## Данные и защита от повторной поломки

- Один JSON-блок `script#site-content` в `index.html` — источник шоу, материалов, контактов, баннеров и кадрирования.
- `content-utils.js` валидирует и безопасно сериализует данные; `site-content.js` читает их без `eval`.
- Админка больше не переписывает JavaScript, CSS или собственный HTML при загрузке материалов. Последовательность `\\n` не превращается в исполняемый код.
- В продакшен не попадают `blob:`-адреса превью. Новые файлы получают новые имена, чтобы старый кэш не скрывал замену.
- Пустые данные, неподдерживаемые файлы и ошибочные ответы не выдаются за успешную публикацию.
- Конкурирующая публикация блокируется, чтобы не затереть изменения другой сессии.
- При сетевом сбое черновик и файлы остаются для повторной попытки. Кнопка блокируется на время публикации.

Онлайн-оплата, билеты и сертификаты не подключены: в этом репозитории нет их рабочего платёжного backend. Текущий публичный заказ, как прежде, идёт через MAX/Telegram; устаревшие формы не должны отправлять фиктивную оплату. Ссылка на отсутствующее пользовательское соглашение заменена ссылкой на контакты; юридические условия не сочинялись.

## Проверки

```bash
npm ci
npm test
# Локальный статический сайт для интеграционных тестов:
python -m http.server 8765 --bind 127.0.0.1
# В другом терминале (после установки Chromium для Playwright):
npx playwright install chromium
npm run test:browser
```

В браузерных тестах GitHub полностью подменён: настоящий токен и настоящий репозиторий не используются. Проверяются вход, сохранение/восстановление черновика с файлами, материалы в двух разных шоу, отдельные мобильные фото, кадрирование, баннеры, контакты, две публикации, сбой/повтор, десять окон шоу и галереи, мобильные кнопки и настоящие touch-свайпы. Для своего Chromium задайте `CHROMIUM_PATH`; для другого локального адреса — `TAIS_TEST_URL`.
